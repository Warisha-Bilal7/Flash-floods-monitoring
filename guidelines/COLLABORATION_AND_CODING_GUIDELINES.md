# FloodWatch KP: Zero-Conflict Collaboration & Coding Guidelines

This guide establishes the frozen collaboration and technical rules for **Person 1 (Qamran)** and **Person 2 (Warisha)**. It guarantees that both developers can write code simultaneously over the 3-day sprint with **zero merge conflicts**, **zero accidental regressions**, and **zero architectural leaks**.

---

## 1. The Three Anti-Conflict Invariants

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. ONE FILE, ONE OWNER                                                 │
│    Every file is exclusively edited by its owner. Nobody touches a     │
│    file owned by the other person without an explicit `cross-owner` PR.│
├────────────────────────────────────────────────────────────────────────┤
│ 2. THE PARQUET INTERFACE                                               │
│    The models (A and B) never import each other and share no code.      │
│    They communicate solely through validated Parquet files.            │
├────────────────────────────────────────────────────────────────────────┤
│ 3. FROZEN CONTRACTS                                                    │
│    Shared schemas, vocabulary, and splits are frozen at D1 11:00.      │
│    Any alteration requires a joint PR signed off by both developers.   │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. Strict Coding Guidelines

### 3.1 Import Boundaries (The PyTorch Isolation Rule)

To guarantee the Streamlit application starts in lightweight serverless containers (like Hugging Face Spaces):

> [!WARNING]
> `torch` and `scikit-learn` may **ONLY** be imported in:
> - `src/floodwatch/models/model_a.py`
> - `src/floodwatch/models/model_b.py`
> - `src/floodwatch/models/eval.py`
> - Model training scripts (`scripts/03_*.py`, `scripts/04_*.py`)

**Strictly Forbidden to import `torch` or `sklearn` in:**
- `fusion.py`, `runner.py`, `interop.py`, `verify.py`, `triage.py`, `explain.py`, `decisions.py`, `messages.py`, `alerts.py`
- `app/streamlit_app.py`

*Automated Enforcement:* `tests/test_app_imports.py` sets `sys.modules["torch"] = None` and verifies that the app and runtime import without error. CI blocks merge if this fails.

---

### 3.2 Package `__init__.py` Policy
- Every `__init__.py` file must remain **completely empty**.
- **No re-exports** (e.g. `from .module import Class` inside `__init__.py`).
- Always import directly from the sub-module:
  ```python
  # CORRECT
  from floodwatch.tiers import Level, tier_to_level
  from floodwatch.schema import validate_predictions

  # FORBIDDEN (Causes circular imports and merge collisions)
  from floodwatch import Level, validate_predictions
  ```

---

### 3.3 Data Structures: Dataclasses over Pydantic
- Do not add `pydantic`.
- Use Python standard library `@dataclass(frozen=True)` for domain models.
- Use `typing.Literal`, `typing.Optional`, and standard Python 3.10+ union syntax (`X | None`).

---

### 3.4 Model Constraints & Limits (Test-Enforced)

```
Model A (Qamran):  CNN-LSTM
├── Max 2 Conv blocks, max 32 filters
├── Max 1 LSTM layer, max 64 units
└── Mandatory Baseline: Logistic Regression

Model B (Warisha): LSTM
├── Strictly 1 LSTM layer, 32 to 64 units
└── Mandatory Baseline: Degree-Day Heuristic
```

- Both models must use **fixed random seeds** and run on **CPU**.
- Parameter shapes are validated by unit tests (`test_model_a.py` and `test_model_b.py`).

---

### 3.5 Model Output Parquet Interface (§3.7)

Each model produces exactly one Parquet file:
- `artifacts/a/predictions_a.parquet` (Qamran)
- `artifacts/b/predictions_b.parquet` (Warisha)

#### Schema Invariants:
1. Columns: `basin_id` (str), `timestamp_utc` (UTC datetime), `module` (str constant), `split` (train/val/test), `prob` (float [0, 1]), `baseline_prob` (float [0, 1]), `source` ("deep"|"baseline"), `top_drivers` (JSON str), `model_version` (str).
2. Unique Key: Exactly one row per `(basin_id, timestamp_utc)`. Sorted ascending.
3. Grid Alignment: Row count and keys must **identically match** `data/processed/grid_index.parquet`.
4. Parquet Metadata: Must store `data_snapshot_hash`, `seed`, `module`, and `trained_at`.
5. Test Rows Exclusion: Model files must **NOT** contain test split rows prior to Milestone M7.

---

### 3.6 Threshold Fitting & Decision Invariant (D-01)
- Thresholds are fitted **strictly on train rows**.
- Mandatory Validation Check: Validation POD must be within 0.10 of train POD, and validation FAR within 0.10 of train FAR.
- If validation degrades, write the failure into `configs/thresholds.yaml` provenance and escalate. **Never silently refit on validation.**

---

### 3.7 Language & Wording Invariants (Trust Layers)
- **Triage Banned Words:** `triage.py` output must **never** contain:
  `fake`, `false`, `hoax`, `untrue`, `debunked`, `not real`, `did not happen`, `never happened`.
  Use `no_signal_found` or `cannot_assess`.
- **Urdu Message Rule:** All Urdu alert templates must retain the **Latin level word** (e.g. `ORANGE`) and **Latin basin ID** (e.g. `swat_kalam`) so that automated verification (`verify.py`) passes without regex relaxation.
- **Single Level Rule:** An alert message must contain exactly one severity level word. Mixed vocabulary (e.g. "Warning" + "RED") must be rejected by `verify.py`.

## 4. Git & Workflow Rules

### 4.1 Branching Strategy
- Never commit directly to `main`.
- Branch naming convention:
  - `qamran/<feature-name>` (e.g. `qamran/openmeteo-ingest`)
  - `warisha/<feature-name>` (e.g. `warisha/fusion-engine`)
- Rebase on `origin/main` before opening a pull request.
- Squash-merge only; delete the feature branch after merge.

### 4.2 Pull Request Rules
- PR size target: **$\le$ 400 lines of code**.
- Mandatory Review: Each PR must be reviewed and approved by the other person. **Zero self-merges.**
- Merge Windows: Synchronize merges at **12:30** and **17:00** daily.
- Never disable or skip failing tests to achieve merge approval.
- Secrets: Zero tokens or keys in code, tests, or config. Use environment variables.

### 4.3 Automated Ownership Enforcement
The CI pipeline runs `python scripts/check_ownership.py`:
- If Qamran touches a Warisha-owned file without the PR label `cross-owner`, the build **fails**.
- If a contract file is modified without the PR label `contract`, the build **fails**.
- If a new file is created without an entry in `OWNERS.yaml`, the build **fails**.
